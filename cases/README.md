## 记录规范

新增案例请按同一结构写，**必须包含**：

1. **环境**：DSH 版本、涉及插件的确切版本、平台、安装形态（Desktop asar / Web）。
2. **实测日期**：结论会过期，日期是它的一部分。
3. **证据**：代码位置（文件 + 关键值）、可复现的操作步骤、或日志片段。
4. **根因**：为什么两个插件会打架（不是"谁做错了"）。
5. **公约如何解决** + 当时的检查器结果。
6. **后续**：相关 PR / issue 链接，以及"如果插件升到 X 版本，本条是否还成立"。

**版本号必须写全**（`0.1.6`，不是"最新版"）。本条规则本身就是为"说不明白"准备的。
